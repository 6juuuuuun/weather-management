# 사내 서버 설치 체크리스트 (회사 노트북에서 그대로 따라 하기)

> 작성 2026-09-07. 개발 담당자가 서버에 직접 붙을 수 없어서, **사내망 노트북을 가진 사람이
> 이 문서대로 명령을 치고 출력을 개발 담당자에게 붙여 주는** 방식으로 설치합니다.
> 한 단계마다 "이 명령 → 이 출력이면 정상"을 적었습니다. 정상이 아니면 **출력을 통째로 복사해
> 개발 담당자에게 보내고 다음 단계로 넘어가지 마세요.**
>
> 명령은 `복사` 버튼으로 통째로 복사해 붙여 넣습니다. `사용자명`, `토큰`처럼 꺾쇠 없이 한글로 쓴
> 자리만 실제 값으로 바꿉니다. 명령 앞의 `$`는 붙이지 않습니다.

## 준비물 — 시작 전에 손에 있어야 하는 것

| # | 항목 | 누가 주는가 | 확인 |
|---|------|------------|------|
| P1 | 서버 IP (`10.58.209.4`) 와 SSH 계정 ID / 비밀번호 | 서버 담당자 | ☐ |
| P3 | 기상청 공공데이터포털 인증키 (**Decoding** 키) | 개발 담당자 | ☐ |
| P4 | 임직원이 접속할 주소. 정해진 게 없으면 `http://10.58.209.4:8080` | 서버 담당자 | ☐ |
| P5 | 첫 관리자로 쓸 본인 회사 이메일 | 본인 | ☐ |

저장소가 **공개**라 GitHub 로그인이나 토큰은 필요 없습니다.

## 1. 서버에 접속하기

회사 노트북에서 **PowerShell**을 엽니다 (시작 메뉴에서 `PowerShell` 검색). Mac이면 터미널.

**1-1. 닿는지 확인**

```powershell
Test-NetConnection 10.58.209.4 -Port 22
```

정상: 마지막 줄 `TcpTestSucceeded : True`
아니면: 노트북이 사내망에 있는지 확인. 그래도 `False`면 서버 담당자에게 "22번 포트가 열려 있나요" 문의.

**1-2. 접속**

```powershell
ssh 사용자명@10.58.209.4
```

- 처음이면 `Are you sure you want to continue connecting (yes/no/[fingerprint])?` → `yes` Enter
- `password:` → 비밀번호 입력 (화면에 아무것도 안 보이는 게 정상) Enter
- 정상: 프롬프트가 `사용자명@서버이름:~$` 로 바뀜

여기부터 아래 명령은 전부 **서버 안에서** 실행합니다.

## 2. 서버 상태 점검 (읽기만 함) → 출력을 개발 담당자에게

아래 블록을 통째로 붙여 넣고 Enter. **출력 전체를 복사해 개발 담당자에게 보냅니다.**

```bash
echo "=== OS ==="; cat /etc/os-release | head -3; uname -r
echo "=== 자원 ==="; nproc; free -h; df -h /
echo "=== 도커 ==="; docker --version 2>&1; docker compose version 2>&1
echo "=== 실행 중 컨테이너 ==="; docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}' 2>&1
echo "=== 열린 포트 ==="; (ss -tlnp 2>/dev/null || netstat -tlnp 2>/dev/null) | grep LISTEN
echo "=== sudo ==="; sudo -n true 2>&1 && echo "sudo 가능(비번없이)" || echo "sudo 비번 필요 또는 불가"
echo "=== git ==="; git --version 2>&1
echo "=== 외부 통신 ==="; curl -s -o /dev/null -w "data.go.kr %{http_code}\n" --max-time 8 https://apis.data.go.kr/; curl -s -o /dev/null -w "npm %{http_code}\n" --max-time 8 https://registry.npmjs.org/; curl -s -o /dev/null -w "github %{http_code}\n" --max-time 8 https://github.com/; curl -s -o /dev/null -w "dockerhub %{http_code}\n" --max-time 8 https://registry-1.docker.io/v2/
```

개발 담당자가 보는 것:

| 줄 | 정상 | 아니면 |
|----|------|--------|
| 도커 | 버전 두 줄 출력 | `command not found` → §3 으로 |
| 실행 중 컨테이너 | 표 출력 | `permission denied` → §3-2 로 |
| 외부 통신 `npm`, `github`, `dockerhub` | `000`이 아닌 숫자 | `github`이 `000` → §4-B 또는 4-C로 갑니다. `dockerhub`·`npm`이 `000` → §4 맨 아래 상자를 읽고 개발 담당자에게 |
| 외부 통신 `data.go.kr` | `000`이 아닌 숫자 | `000` → 설치는 계속하되, 서버 담당자에게 "서버 → apis.data.go.kr 443 아웃바운드 허용" 요청. 이게 막히면 날씨 수집이 안 됩니다 |

## 3. Docker 준비 (§2에서 도커가 없거나 권한이 없을 때만)

**3-1. Docker가 없을 때**

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
```

정상: 마지막에 오류 없이 끝나고 `docker --version`이 버전을 출력.

**3-2. `permission denied`가 났을 때** (docker를 이 계정으로 쓸 권한이 없음)

```bash
sudo usermod -aG docker $USER
exit
```

`exit`로 **접속이 끊기는 것이 정상**입니다. §1-2 로 다시 접속한 뒤 확인:

```bash
docker ps
```

정상: 표 머리글(`CONTAINER ID  IMAGE ...`)이 나옴. 여전히 `permission denied`면 개발 담당자에게.

**3-3. git이 없을 때**

```bash
sudo apt-get update && sudo apt-get install -y git curl
```

(Ubuntu/Debian 기준. `apt-get: command not found`면 §2 출력의 OS 줄을 개발 담당자에게 알려 주세요.)

## 4. 코드 받기

§2에서 본 `github` 줄에 따라 갈립니다. **셋 중 하나만** 하면 됩니다.

### 4-A. `github` 이 ✅ 나감 → 그냥 받습니다 (대부분 여기)

```bash
git clone https://github.com/6juuuuuun/weather-management.git ~/weather
```

이 명령이 하는 일: GitHub에 있는 코드 전체를 서버의 `~/weather` 폴더로 내려받습니다.
저장소가 **공개**라 로그인도 토큰도 필요 없습니다.

정상: `Cloning into '/home/사용자명/weather'...` 로 시작해 오류 없이 끝남.
- `Could not resolve host` → 서버가 github.com 에 못 나갑니다. **4-B** 로 갑니다.

### 4-B. `github` 이 ❌ 막힘 → 사내 Gitea를 거칩니다

서버는 못 나가도 **사내 Gitea는 나갈 수 있는 경우가 많습니다.** 한 번 올려 두면
그 뒤로는 서버가 Gitea에서 받으면 되고, 코드가 바뀔 때마다 사람이 파일을 옮길
필요가 없습니다.

**① 사내 PC 브라우저에서** Gitea에 로그인한 뒤

1. 오른쪽 위 **+** → **새 마이그레이션**(New Migration)
2. **GitHub** 선택 (없으면 **Git**)
3. 복제 주소: `https://github.com/6juuuuuun/weather-management.git`
4. 인증란은 **비워 둡니다** (공개 저장소)
5. 저장소 이름: `weather-management`
6. ☑ **이 저장소를 미러로 만듭니다** — 체크하면 Gitea가 GitHub를 주기적으로
   스스로 따라옵니다. 개발 담당자가 코드를 고치면 잠시 뒤 Gitea에도 반영됩니다.
7. **마이그레이션** 클릭

커밋 이력이 그대로 보이면 성공입니다.
실패(`Could not resolve host`·시간 초과)하면 Gitea도 밖으로 못 나가는 것이니 **4-C**.

**② 서버에서** — 방금 만든 사내 주소에서 받습니다

```bash
git clone http://<Gitea주소>/<계정>/weather-management.git ~/weather
```

### 4-C. Gitea도 못 나감 → 파일 하나로 옮깁니다

개발 담당자에게 **`weather-main.bundle`**(약 4.5MB)을 요청하세요. 저장소 전체
이력이 담긴 파일 하나이고, USB·메신저 등 반입이 허용된 수단으로 옮깁니다.

**사내 PC에서** — 파일을 저장소로 되살려 Gitea에 올립니다

```bash
git clone weather-main.bundle weather-management
cd weather-management
git remote remove origin
git remote add origin http://<Gitea주소>/<계정>/weather-management.git
git push -u origin main
```

**서버에서** — 4-B ②와 같습니다.

### 받은 뒤 확인 (A·B·C 공통)

```bash
cd ~/weather && ls ops/install.sh && git log --oneline -1
```

정상: `ops/install.sh` 와 최근 커밋 한 줄이 나옵니다.

> **`dockerhub`·`npm` 이 ❌ 였다면** 코드는 들어왔어도 §5의 빌드가 부품을 못 받아
> 멈춥니다. §2 출력을 개발 담당자에게 보내면 부품까지 담긴 파일(약 400~600MB)을
> 만들어 줍니다. 그때는 서버의 `uname -m` 결과도 함께 알려 주세요 — CPU 종류가
> 다르면 실행 자체가 되지 않습니다.

## 5. 설치 스크립트 실행 → 출력 전체를 개발 담당자에게

```bash
cd ~/weather && ./ops/install.sh
```

스크립트가 알아서 8단계를 진행합니다. 처음 설치라면 **세 가지를 묻습니다.**

| 질문 | 넣을 값 |
|------|--------|
| 기상청 공공데이터포털 인증키(Decoding) | P3 |
| 임직원이 접속할 주소 `[http://10.58.209.4:8080]` | P4. 기본값이 맞으면 그냥 Enter |
| 가입을 허용할 이메일 도메인 `[gonjiam.com]` | 회사 이메일 도메인. 맞으면 그냥 Enter |

그다음 **5~15분** 걸립니다(화면 빌드). 아무것도 안 나오는 것처럼 보여도 기다립니다.

정상: 마지막에 아래 상자가 보임.

```
========================================================================
  설치 완료

  화면 주소     : http://10.58.209.4:8080
  ...
```

그 위 `[8/8] 상태 확인` 에 아래 두 줄이 있어야 합니다.

```
  ✔ app · postgres 모두 healthy
  ✔ 데이터베이스 스키마 적용됨 (마이그레이션 17건 기록, 앱 계정 2개)
```

그 아래 `/api/health/deep 응답` 은 처음 설치 직후에는 **`⚠ 사유 4건`** 이 정상입니다. 관리자가 아직 없고
행동지침·수신자를 넣기 전이라 시스템이 "아직 아무에게도 알릴 수 없다"고 정확히 말하는 것입니다.
§7 을 끝내면 사유가 줄어들고, 최종적으로 `SMS 발송 설정이 아직 없습니다` 하나만 남으면 문자 연동 외
준비가 끝난 것입니다.

`✘` 로 멈췄으면: 그 아래 "여기서 멈춥니다" 까지 **출력 전체**를 개발 담당자에게. 고친 뒤 같은 명령을
다시 돌리면 이어서 진행됩니다(이미 한 일은 건너뜁니다).

> 포트 8080 을 다른 프로그램이 쓰고 있으면 스크립트가 8081 처럼 빈 포트를 골라 씁니다.
> 그때는 "화면 주소"의 포트가 바뀌어 있으니 **그 주소를 그대로 사용**하고, 개발 담당자에게도 알려 주세요.

## 6. 브라우저로 확인 (회사 노트북)

노트북 브라우저에서 §5 의 "화면 주소"를 엽니다. 예: `http://10.58.209.4:8080`

정상: 날씨경영 로그인 화면.
아니면: 노트북 → 서버 8080 이 막힌 것. 서버 담당자에게 "임직원 PC → 서버 8080 허용" 요청.
(서버 안에서는 `curl -s localhost:8080/api/health` 가 `{"ok":true...}` 류를 돌려주면 서버 자체는 정상.)

## 7. 첫 관리자 만들기 (반드시)

1. 브라우저에서 **회사 이메일(P5)로 가입**합니다.
2. 서버 터미널에서 (이메일 자리를 가입한 이메일과 **철자 그대로**):

```bash
cd ~/weather && ./ops/make-admin.sh 이메일@회사도메인
```

정상: `관리자로 지정했습니다: 이메일@회사도메인`
`그런 직원이 없습니다` → 가입한 이메일과 철자가 다릅니다. 다시 확인.

3. 브라우저에서 **로그아웃 후 다시 로그인** → 관리자 메뉴가 보임.
4. 대시보드의 **셋업 체크리스트**를 순서대로 진행합니다 (관측 지점 좌표 → 특보 기준 → 부서 →
   행동지침 → 수신자). 내용은 `docs/배포-준비-체크리스트.md` §3.

## 8. 백업 걸기 (10분, 나중에 후회하지 않으려면 지금)

**8-1. 폴더 만들고 한 번 떠 보기**

```bash
sudo mkdir -p /backup/weather && sudo chown "$USER" /backup/weather
cd ~/weather && BACKUP_DIR=/backup/weather ./ops/backup.sh
```

정상: `백업 완료(검사 통과): /backup/weather/weather-2026....sql.gz (숫자바이트)`
**"(검사 통과)"가 붙어야 성공**입니다.

**8-2. 매일 새벽 자동 백업**

```bash
( crontab -l 2>/dev/null; echo "0 3 * * * cd $HOME/weather && BACKUP_DIR=/backup/weather ./ops/backup.sh >> /backup/weather/backup.log 2>&1"; echo "30 3 * * 1 cd $HOME/weather && ls -t /backup/weather/weather-*.sql.gz | head -1 | xargs ./ops/verify-backup.sh >> /backup/weather/backup.log 2>&1" ) | crontab -
crontab -l
```

정상: 마지막에 `0 3 * * * ...` 과 `30 3 * * 1 ...` 두 줄이 보임.

> 백업 파일은 가능하면 서버 밖(NAS·다른 디스크)에 두는 것이 원칙입니다. 지금은 서버 안 `/backup` 에
> 두고, 서버 담당자에게 외부 저장 위치를 문의해 두세요. (`docs/운영.md` §4)

## 9. 나중에 코드가 새 버전이 되었을 때

개발 담당자가 "새 버전 올려 주세요"라고 하면:

```bash
cd ~/weather && git pull && ./ops/install.sh
```

토큰이 만료되어 `git pull` 이 `Authentication failed` 를 내면, 새 토큰(P2)을 만든 뒤:

```bash
cd ~/weather && git remote set-url origin https://oauth2:새토큰@github.com/6juuuuuun/weather-management.git && git pull
```

## 10. 문제가 생겼을 때 개발 담당자에게 보낼 것

아래 블록을 서버에서 실행해 **출력 전체**를 보냅니다. 비밀번호는 출력에 포함되지 않습니다.

```bash
cd ~/weather
echo "=== ps ==="; docker compose ps -a
echo "=== health ==="; curl -s -m 5 localhost:${APP_HOST_PORT:-8080}/api/health; echo; curl -s -m 10 localhost:${APP_HOST_PORT:-8080}/api/health/deep; echo
echo "=== migrate 로그 ==="; docker compose logs --no-color --tail 60 migrate
echo "=== app 로그 ==="; docker compose logs --no-color --tail 120 app
echo "=== disk ==="; df -h / ; docker system df
```

## 11. 아직 하지 않은 보안 조치 (서버 담당자와 별도로 결정)

이 서버는 방화벽과 SSH 접근 제한이 없는 상태로 받았습니다. 설치 스크립트는 **보안 설정을 건드리지
않습니다**(다른 컨테이너가 쓰는 포트를 막아 버릴 수 있어서). 서비스가 뜬 뒤 서버 담당자와 아래를
정하세요.

- [ ] SSH: 비밀번호 로그인 대신 키 로그인만 허용, 접속 가능 IP 제한
- [ ] 방화벽(ufw 등): 22, 8080 과 **기존 컨테이너가 쓰는 포트**만 열고 나머지 차단
- [ ] 8080 은 사내망에서만 접근 가능한지 확인 (외부 인터넷에서 열리면 안 됨)
- [ ] `~/weather/.env` 백업 — 이 파일이 없어지면 데이터베이스에 다시 접속할 수 없음
