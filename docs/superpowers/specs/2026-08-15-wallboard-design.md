# 월보드(전체화면 대시보드) — 설계 문서

- 날짜: 2026-08-15
- 상태: 설계 승인 완료 (사용자 승인 2026-08-15)
- 관련: `DESIGN-apple.md` (디자인 규범), `docs/superpowers/specs/2026-08-12-weather-management-design.md`
- 시안: 실제 관측 데이터로 4개 상태를 렌더링해 확정 (스크래치 `board.html`, 커밋하지 않음)

## 1. 목적

대시보드를 전체화면으로 띄워 **조작하지 않고 관망하는 표시면**으로 쓴다. 두 곳에서 같은 화면을 공용한다.

- 사무실·상황실 대형 모니터에 상시 표시 (아무도 조작하지 않음, 3미터 밖에서 읽힘)
- 관리자 PC에서 필요할 때 전환

야간 모드는 두지 않는다(사용자 결정) — 밝은 화면 하나로 간다.

## 2. 진입과 유지

기존 대시보드(`/`)에 전체화면 버튼을 둔다. 별도 라우트를 만들지 않는다(사용자 결정 B안).

- 버튼 → 브라우저 Fullscreen API 전환 + URL에 `?board=1`
- URL 파라미터를 남기는 이유: 벽걸이 기기가 이 주소를 북마크하면 부팅 후 바로 월보드로 들어간다
- `ESC`로 해제, 파라미터 제거
- 세션은 `autoRefreshToken` 기본값으로 무기한 유지되므로 추가 작업 없음

## 3. 보드 모드에서 달라지는 것

| | 일반 대시보드 | 보드 모드 |
|---|---|---|
| 상단 네비게이션 | 표시 | **숨김** |
| 초기 설정 체크리스트 | 표시 | **숨김** |
| "설정 계속하기"·"초안 검토하기" 버튼 | 표시 | **숨김** |
| 부서 미지정 안내 배너 | 표시 | **숨김** |
| 상태 헤드라인 | 없음 | **추가** |
| 지표 카드 | 4열, 숫자만 | **2×2, 숫자 + 차트** |
| 하단 티커 | 없음 | **추가** |

조작 요소를 전부 걷어내는 것이 핵심이다. 아무도 누르지 않는 화면에 버튼이 있으면 정보 밀도만 낮춘다.

## 4. 화면 구성

### 4.1 헤더

좌측에 상태 한 단어를 가장 크게(64px/600). 3미터 밖에서 이 한 줄만 봐도 상황을 안다.

| 상태 | 표기 | 색 |
|---|---|---|
| 열린 특보 없음 | `평온` | `--ink` |
| 승인 대기 특보 있음 | `특보 발생` | `--danger` |
| 전부 발송 완료 | `대응 중` | `--danger` |

우측에 현재 시각(44px/300)과 `마지막 수집 N분 전`.

### 4.2 특보 배너

열린 특보가 있을 때만 헤더 아래에 나타난다. 화면 구조가 바뀌므로 멀리서도 "무슨 일이 생겼다"가 즉시 읽힌다.

각 배너: 상태 배지(`승인 대기` / `발송 완료`) + 제목(`폭우 경보`) + 상세(`13:05 감지 · 초안 5개 부서 · 재알림 2회`).

**2건 이상이면 가로 배치.** 세로로 쌓으면 카드 영역이 줄어 차트가 잘린다(시안에서 실측 확인). `one_open_event` 인덱스가 (종류, 등급) 단위라 폭우 경보와 강풍 주의보가 동시에 열릴 수 있으므로 3건까지는 실제로 발생한다.

### 4.3 지표 카드 2×2

강수량 · 기온 · 풍속 · 체감온도. 각 카드에 라벨, 큰 숫자(68px/600), 최근 24시간 차트.

**4열 1행이 아니라 2×2인 이유**는 16:9 화면에서 4열은 카드가 세로로 과하게 길어져 숫자와 차트 사이가 비기 때문이다(시안에서 실측 확인). 2×2는 카드가 정사각형에 가까워 차트가 가로로 펴진다.

숫자 색은 현재 상태를 따른다 — 평온 `--ink`, 임계의 90% 이상 `--warn-strong`, 초과 `--danger`.

### 4.4 차트

각 카드 안 인라인 SVG. 외부 차트 라이브러리를 넣지 않는다 — 필요한 것이 선 하나와 기준선뿐이고, 앱 번들이 이미 340KB이며, 디자인 토큰에 맞추기도 직접 그리는 편이 정확하다.

**적응형 스케일.** 평소에는 데이터 범위에 맞추고, 임계가 사정권(데이터 폭의 70% 이내)에 들면 스케일에 포함해 기준선이 시야로 들어온다. 평온한 날에는 추이가 잘 보이고, 위험해질수록 기준선이 나타나 간격이 좁혀지는 것이 보인다.

**축 하한 0 고정 (강수·풍속·적설).** 물리적으로 음수가 없는 값이다. 고정하지 않으면 전부 0인 날 축이 `-1.3mm`까지 내려간다(시안에서 실제 발생).

**임계 분할 면적.** 기준선 아래는 뮤트(불투명도 0.10), 위는 경고색(0.26). 이것이 이 차트의 핵심이다 — 현재값이 0이라 선은 회색이어도 **오늘 몇 번, 얼마나 넘었는지**가 색으로 남는다. 상황실에서 "지금은 괜찮은데 오늘 어땠나"를 차트가 혼자 답한다.

**값이 전부 동일하면** 면적을 칠하지 않고 `변화 없음`을 표시한다. 비가 안 온 날 면적이 차 있으면 "쌓여 있다"로 오독된다.

기준선은 1px 점선, 라벨(`주의보 20mm`)은 **좌측**에 흰 칩을 깔고 놓는다. 우측은 최신값이 있어 겹친다.

선 2px, 마지막 점 반지름 6px에 표면색 2.5px 링, 격자 없음, 라벨은 잉크 토큰.

### 4.5 티커

하단 고정. `--surface-black` 배경에 흰 글씨 — 이 시스템에서 순수 검정은 글로벌 네비에만 쓰이므로, 화면 최하단 띠로서 문법이 맞는다.

지표 4개를 순환한다. 형식:

- 미달: `기온 28.9℃ · 폭염 주의보까지 4.1℃`
- 초과: `시간당 강수량 31mm · 폭우 주의보 기준 초과 +11.0mm` (초과분은 `--warn-strong`, 600)

CSS 애니메이션으로 흐르며, 트랙을 2벌 이어붙여 끊김 없이 순환한다.

## 5. 디자인 규범 준수

`DESIGN-apple.md`가 금지하는 것 중 초기 시안이 어겼다가 바로잡은 것들이다. 구현 시에도 지킨다.

- **장식 띠 금지** — 강조는 표면 색 변화로 만든다. 특보 배너에 좌측 색 띠를 두지 않는다. 기존 `.obs-card-warn`도 띠 없이 숫자 색만 바꾼다
- **카드에 그림자 금지** — 이 시스템의 유일한 그림자는 제품 렌더용이다
- **장식 그라데이션 금지** — 차트 면적은 평면 반투명으로 채운다
- **반경 문법 혼용 금지** — 카드·배너는 `rounded.lg`(18px), 배지는 pill. 그 사이 값을 쓰지 않는다
- **두 번째 강조색 금지** — 상호작용 색은 Action Blue 하나. 경고·위험색은 상태 전용이며 계열색으로 쓰지 않는다

## 6. 색 검증

주의보와 경보가 한 화면에 동시에 나타나므로 두 색이 구분돼야 한다. 현재 토큰의 `--warn (#a65a00)`은 `--danger (#d70015)`와 **적록색각이상에서 ΔE 1.6** — 사실상 같은 색이다(정상 시각에서도 13.4로 기준 15 미달).

**월보드는 `--warn-strong (#ff9500)`을 쓴다.** `#ff9500` ↔ `#d70015`는 전 검사 통과(색각이상 ΔE 21.2, 정상 24.9, 대비 3:1 이상).

배지에 "주의보"/"경보" 글자가 함께 있으므로 색이 유일한 신호는 아니지만, 3미터 밖에서는 글자가 안 읽혀 색이 사실상 유일한 채널이 된다.

기존 화면의 배지 색을 바꾸는 것은 이번 범위 밖이며 별도 결정 사항이다.

## 7. 구조

라우트는 하나로 유지하되(B안), 파일을 나눈다. `Dashboard.tsx`가 이미 510줄이라 보드 레이아웃을 그대로 넣으면 두 목적을 한 파일이 지게 된다.

| 파일 | 책임 |
|---|---|
| `apps/web/src/pages/useDashboardData.ts` | 기존 `load` 로직 추출. 두 모드가 공유 |
| `apps/web/src/pages/DashboardBoard.tsx` | 보드 레이아웃 |
| `apps/web/src/components/MetricChart.tsx` | 적응형 스케일 + 임계 분할 SVG 차트 |
| `apps/web/src/components/BoardTicker.tsx` | 하단 티커 |
| `apps/web/src/pages/Dashboard.tsx` | `?board=1`이면 `DashboardBoard`를, 아니면 기존 레이아웃을 렌더 |

### 7.1 데이터

기존 `DashboardData`에 차트용 이력을 더한다.

```ts
type ObservationPoint = {
  observed_at: string;
  rain_mm_per_hr: number | null;
  temp_c: number | null;
  feels_c: number | null;
  wind_ms: number | null;
};
// 최근 24시간, missing=false. 기존 관측 쿼리와 같은 기준.
history: ObservationPoint[];
```

쿼리 하나가 추가된다. 기존 폴링 주기(30초)를 그대로 쓴다.

## 8. 엣지 케이스

| 상황 | 동작 |
|---|---|
| 관측 이력 0건 | 카드에 숫자만, 차트 자리는 비움 |
| 이력이 1건뿐 | 점 하나. 선을 그리지 않는다 |
| 이력에 결측 구간 | 결측 행은 제외하고 남은 점을 잇는다(대시보드 관측 쿼리와 같은 기준) |
| 값이 전부 동일 | 면적 없이 `변화 없음` |
| 임계가 데이터 범위 밖 | 기준선을 그리지 않는다. 근접도는 티커가 전담 |
| 열린 특보 4건 이상 | 가로 배치가 좁아지므로 3건까지 표시하고 `외 N건`으로 접는다 |
| 전체화면 API 거부(브라우저 정책) | 파라미터만 적용해 레이아웃은 보드로 바뀐다. 기능이 막히지 않는다 |

## 9. 테스트

- **차트(순수 함수)**: 적응형 스케일이 임계를 포함/제외하는 경계, 물리량 축 하한이 0 아래로 내려가지 않음, 전부 동일값일 때 평탄 처리, 임계 분할 경계
- **티커**: 미달/초과 문구 분기, 초과분 계산
- **보드 모드**: `?board=1`일 때 조작 요소(네비·체크리스트·CTA)가 렌더되지 않음
- **회귀**: 보드 모드가 아닐 때 기존 대시보드가 그대로임

## 10. 범위 밖

- 야간(다크) 모드 — 사용자 결정으로 제외
- 예보 연동 — 현재 초단기실황만 수집한다. 티커에 예보를 흘리려면 별도 API 연동이 필요하다
- 기존 화면의 배지 색 교체 (6절)
- 차트 호버·툴팁 — 벽걸이 화면에 포인터가 없다. 관리자 PC에서는 일반 대시보드를 쓰면 된다
