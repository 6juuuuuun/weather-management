# 월보드 — 후속 이슈

`feat/wallboard`(1c9efdb..cda8210) 최종 전체 리뷰에서 나왔으나 머지를 막지 않아
분리한 항목이다. 리뷰어가 실제로 실행해 확인한 것만 적었다. 우선순위 순.

## 1. 값이 전부 같고 0이 아니면 "면적 + 변화 없음"이 동시에 뜬다

`apps/web/src/components/MetricChart.tsx` — 면적 억제 조건이 `flat`이 아니라 `allZero`.

```
[6,6,6],  임계 14 → mc-area-below 렌더 + "변화 없음" 동시 표시
[30,30,30], 임계 20 → 기준선 + 초과 구간 채색 + "변화 없음" 동시 표시
```

두 번째가 나쁘다 — "오늘 임계를 넘긴 구간"이 칠해진 채 그 위에 "변화 없음"이 겹쳐
3미터 밖에서 모순된 두 신호를 낸다. 풍속이 6m/s로 일정한 날은 드물지 않다.
관측 이력이 1건뿐일 때도 같은 분기를 타서 "변화 없음"이 뜬다(스펙 §8은 "점 하나"만 요구).

**결정이 필요하다**: 스펙 §4.4/§8 문구("값이 전부 동일하면")를 정본으로 볼지,
현재 구현(전부 0일 때만)을 정본으로 볼지. 전자면 조건을 `flat`으로 바꾸면 된다.

## 2. 차트가 카드 폭을 못 채우고 가운데 뜬다

`apps/web/src/components/MetricChart.css` — `height: 100%` + `preserveAspectRatio`
기본값(`xMidYMid meet`)이 좌우 레터박싱을 만든다.

| 뷰포트 | 한쪽 여백 |
|---|---|
| 1920×1080 (벽걸이) | 0px |
| 2560×1440 | 19.6px |
| 1512×707 | 40.3px |
| 1512×600 | 81.6px |

벽걸이는 무해하고 **와이드·저높이 노트북에서만** 차트가 카드 폭의 87%→74%로 줄고,
스펙 §4.4가 좌측 배치를 요구한 기준선 칩과 축 라벨이 안쪽으로 밀린다.
`preserveAspectRatio="xMinYMid meet"` 한 속성이면 좌측 정렬은 회복된다.

부수 효과: 지금 SVG가 0.65~1.0으로 축소 렌더돼 **선 굵기가 실효 1.6~2.5px로 변한다**
(스펙은 2px). 이 항목을 정리한 뒤 굵기를 재산정하는 것이 순서다.

## 3. `DESIGN-apple.md` 이탈 2건

- `MetricChart.tsx` 기준선 칩 `rx="4"` — 규범은 8/18/pill 사이 값을 금한다.
- `DashboardBoard.css`의 `.bd-event-detail`·`.bd-card-label`에 `line-height: 1.1`
  — 규범은 본문 1.47 미만을 금한다. vh 산수를 맞추려고 넣은 것이라,
  되돌리면 배너 높이가 늘어 1번 항목의 여유(최악 9.3px)를 다시 봐야 한다.

## 4. 전체화면 버튼이 디자인 시스템을 우회한다

`Dashboard.tsx`가 공용 `Button` 대신 raw `<button>`을 쓰고, `Dashboard.css`가
이미 있는 `.btn-ghost`(pill, `--primary`, hover/focus 상태 보유)를 복제했다.
`:hover`/`:focus-visible` 없고 높이 ≈37px로 규범의 44px 최소 타겟 미달.

## 5. "미설정 임계" 센티널을 `null`로 승격

`Dashboard.tsx`의 `toBoardProps`가 `?? 0`으로 넘기고 하류 셋이 `> 0`으로 되받는다.
현재 4종 지표가 전부 양수라 동작은 맞지만, 이 브랜치는 **이미 한 번 이 센티널 혼동으로
수정 라운드를 소모했다**(T4-R1). `?? null` + 하류 `!== null`로 통일하면 개념이 영구히 닫힌다.
한파 등 음수 임계 지표를 추가하는 시점에는 필수가 된다.

## 6. 보드 모드 탈출구가 전체화면 API에만 달려 있다

벽걸이가 `?board=1`을 북마크해 진입한 경우(전체화면 아님)나 브라우저가
`requestFullscreen`을 거부한 경우, 화면에 조작 요소가 없어 URL 편집 외에 나올 방법이 없다.
역방향도 있다 — 다른 요소가 전체화면을 빠져나오면 벽걸이의 `board` 파라미터가 조용히 사라진다.
스펙 §8은 "기능이 막히지 않는다"만 적었고 복귀 경로를 정의하지 않았다.

## 7. `prefers-reduced-motion: reduce`에서 티커가 첫 항목만 영구 표시

`BoardTicker.css`가 애니메이션을 끄면 `translateX(0)`에 고정돼 뒤쪽 지표를 볼 수 없다.
카드에 숫자는 있으므로 정보 전손은 아니지만, 티커의 존재 이유인 "임계까지 남은 거리"가
앞 1~2개만 노출된다.

## 8. 자잘한 것

- **`-999` 센티널**: `supabase/functions/_shared/kma.ts`의 `Number(v)`가 KMA 결측
  센티널을 거르지 않는다. `missing=false`인 `-999` 행이 있으면 축 상한이 172.85까지
  튄다(붕괴는 없고 표시만 무의미). **이 브랜치가 만든 결함이 아니며 일반 대시보드도
  `-999.0mm`를 그대로 표시한다** — 수집 단계에서 거르는 것이 맞다.
- **스펙 §4.1 문구 불일치**: 스펙은 `마지막 수집 N분 전`인데 구현은 `HH:MM 관측 기준`
  (prop 이름은 여전히 `collectedAgo`). 구현 쪽이 더 정확하므로 스펙을 고치는 편이 낫다.
- **모드 전환 재조회에 전용 테스트 없음**: `load`의 deps에 `boardMode`가 있어 동작하지만,
  `.oxlintrc.json`에 `exhaustive-deps`가 없어 누가 deps에서 빼도 린트·tsc 모두 침묵한다.
  결과는 "보드로 전환했는데 차트가 영원히 빈 화면". 클릭 테스트에 단언 한 줄이면 닫힌다.
- **`gradeLabel` 이중 출처**: `DashboardBoard.tsx`가 차트에 리터럴 `"주의보"`를 넘긴다.
  현재 임계가 전부 `watch`에서만 오므로 결과는 맞지만, 경보 임계를 넣으면 차트만 거짓말한다.
- **죽은 주석**: `chartScale.test.ts`의 "60% 이내"(실제 70%), `Dashboard.tsx`의 "최대 1분"
  (`POLL_MS=30_000` 기준 과장).
- **평탄+음수허용에서 칩이 축 라벨과 겹친다**: `computeScale([32,32,32], 33, true)`에서
  칩(y −1~19)과 축 상한 라벨(y ≈1~12)이 충돌. 기온이 24시간 완전 고정이어야 발생.
- **CSS 계약 가드는 단위만 본다**: `padding: 0.01vh`도 통과한다. 실제 넘침 판정은
  브라우저 실측이 필요하고 그건 CI에 없다.
