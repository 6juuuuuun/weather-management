# 사내 서버 배포 준비 체크리스트

> 작성 2026-09-05 · 코드는 완성 상태이고, 남은 것은 **인프라 자료**와 **운영 데이터 입력**입니다.
> 설치·운영 절차 자체는 [`운영.md`](운영.md)를 보세요. 이 문서는 **배포 전에 확보해야 할 것**의 목록입니다.

현재 상태를 한 줄로 확인하는 법:

```bash
cd ~/weather && curl -s localhost:8080/api/health/deep
```

사유가 아래 **하나만** 남으면 문자 연동을 빼고 모든 준비가 끝난 것입니다.

```
"SMS 발송 설정이 아직 없습니다 — 인프라 연동 대기 중"
```

---

## 1. 인프라팀에 요청할 것 (문자 발송 연동)

가장 오래 걸리는 항목입니다. **가장 먼저 보내세요.**

- [ ] **1-1. 문자 발송 업체명** (예: NHN Toast, NCP SENS, 알리고 등)
- [ ] **1-2. API 연동 문서** (URL 또는 파일)
- [ ] **1-3. API 인증 정보** — API Key / Secret / 계정 ID
- [ ] **1-4. 발신번호** ※ 국내 발신번호 사전등록제 대상
- [ ] **1-5. 발신번호의 통신사 사전등록 완료 여부**
- [ ] **1-6. LMS(장문) 지원 여부와 1건당 최대 바이트** ※ 현재 2,000바이트로 구현돼 있음
- [ ] **1-7. 일/월 발송 한도와 과금 방식**
- [ ] **1-8. 테스트(샌드박스) 환경 제공 여부**
- [ ] **1-9. 사내 서버 → 문자 API 도메인 아웃바운드 HTTPS(443) 허용 여부**

> **1-9를 반드시 함께 물어보세요.** 계정만 받고 방화벽이 막혀 있으면 그 자리에서 다시 대기하게 됩니다.
> 실제로 가장 자주 누락되는 항목입니다.

### 요청 메일 예시 (그대로 복사해 사용)

```
[날씨경영 시스템] 문자(LMS) 발송 연동을 위한 자료 요청

사내 서버에서 임직원에게 기상특보 문자를 자동 발송하려 합니다.
아래 자료를 부탁드립니다.

■ 발송 서비스
 1. 사용 중인 문자 발송 업체명 (예: NHN Toast, NCP SENS, 알리고 등)
 2. API 연동 문서 (URL 또는 파일)
 3. API 인증 정보 (API Key / Secret / 계정 ID)

■ 발신번호  ※ 국내 발신번호 사전등록제 대상
 4. 사용할 발신번호
 5. 해당 번호의 통신사 사전등록 완료 여부

■ 사양 확인
 6. LMS(장문) 지원 여부 및 1건당 최대 바이트  ※ 저희는 2,000바이트로 구현
 7. 일/월 발송 한도 및 과금 방식
 8. 테스트(샌드박스) 환경 제공 여부

■ 네트워크  ※ 이것이 막히면 위 자료가 있어도 발송 불가
 9. 사내 서버 → 문자 API 도메인 아웃바운드 HTTPS(443) 허용 가능 여부
```

## 2. 서버 담당자에게 확인할 것 (네트워크·사양)

문자 연동과 **별개로** 시스템이 도는지를 가릅니다.

- [ ] **2-1. 서버 → `apis.data.go.kr` 아웃바운드 허용 여부**
  안 되면 **기상청 수집이 통째로 멈춥니다.** 이 시스템이 할 일이 없어집니다. **가장 중요합니다.**
- [ ] **2-2. 서버 → npm 레지스트리 접근 가능 여부**
  안 되면 `docker compose up -d --build`가 실패합니다 → 아래 "폐쇄망일 때" 참고
- [ ] **2-3. 임직원 PC → 서버 8080 포트 접근 가능 여부**
  안 되면 아무도 화면에 들어오지 못합니다. (다른 포트를 써야 하면 `.env`의 `APP_HOST_PORT`)
- [ ] **2-4. Docker 설치 여부**
- [ ] **2-5. 디스크 여유** — 백업 포함 최소 20GB 권장
- [ ] **2-6. 재부팅 정책** (윈도우 업데이트·정전) — 컨테이너는 자동 복구되도록 이미 설정돼 있음

### 폐쇄망(2-2가 불가)일 때

`git pull` + `--build` 방식을 쓸 수 없습니다. 대신:

```
1. 인터넷 되는 PC에서 이미지 빌드
2. docker save 로 파일로 저장
3. USB / 내부망으로 서버에 전달
4. 서버에서 docker load
```

이 경우 서버에 git도 빌드 도구도 필요 없습니다. **해당되면 알려주세요 — 그 절차로 다시 준비합니다.**

## 3. 운영 데이터 입력 (자료를 기다리지 않고 지금 할 수 있음)

`migrate`가 넣어 주는 기본값은 **부서 트리 · 특보 기준 · 알림 설정**까지입니다.
**행동지침은 비어 있습니다** — 조직마다 다른 내용이라 시스템이 만들어 낼 수 없습니다.

관리자로 로그인한 뒤 대시보드의 **셋업 체크리스트**를 순서대로 끝내세요.

- [ ] **3-1. 관측 지점** — 알림 설정 → `관측 지점`에 지점명·주소와 기상청 격자좌표(nx, ny)
  **좌표가 틀리면 수집이 통째로 멈춥니다.** nx는 1~149, ny는 1~253
- [ ] **3-2. 특보 기준** — 4종(폭우·폭설·강풍·폭염) × 2등급 임계값 확인 (기본값 있음)
- [ ] **3-3. 부서 구성** — 직원 관리 → 부서 관리에서 트리 확인·수정 (기본 트리 있음)
  부서를 옮길 때는 **지우고 새로 만들지 말고** `상위 부서` 칸에서 변경하세요.
  지우면 지침과 수신자 지정이 함께 사라지고, 옮기면 따라갑니다.
- [ ] **3-4. 부서별 행동지침** — 행동 지침 화면에서 종류 × 등급 × 부서마다 입력 ← **가장 오래 걸림**
- [ ] **3-5. 부서 수신자** — 지침을 등록한 부서에는 반드시 함께 지정
- [ ] **3-6. Alert 수신자** — 특보 기준 → 맨 아래 `특보 Alert 수신자`
- [ ] **3-7. 수신자 휴대폰 번호** — 직원 관리 화면의 `휴대폰` 칸이 "있음"인지 확인

### ⚠️ 3-4를 비워 두면 문자가 "내용 없이" 나가는 게 아니라 **아예 안 나갑니다**

지침이 곧 발송 대상(부서)이라, 비어 있으면 초안이 통째로 비고 승인 버튼도 눌리지 않습니다.

### ⚠️ 승인 권한은 역할이 아니라 3-6의 목록에서 나옵니다

- 역할을 `승인자`로 올려도 **승인 권한은 생기지 않습니다** — 이 목록에 넣어야 합니다
- 역할이 `실무자`인 사람도 이 목록에 있으면 **승인할 수 있습니다**
- 권한을 회수하려면 역할을 낮추는 것이 아니라 **이 목록에서 빼야 합니다**

승인 요청 문자를 받는 사람과 승인할 수 있는 사람이 정의상 같아야 하므로 이렇게 정했습니다
(두 목록이 어긋나 승인이 멈춘 사고가 있었습니다).

### 길이 상한

지침 한 항목 200자 · 한 부서/종류/등급당 20개 · 고객 안내 멘트 1,000자.
문자 한 통(LMS)은 **2,000바이트 = 한글 약 666자**입니다.
넘치면 뒷부분이 잘리고 그 자리에 안내와 링크가 붙으며, **넘칠 것 같으면 `/api/health/deep`이 미리 알려 줍니다.**

## 4. 자료를 받은 뒤 (반나절)

- [ ] **4-1.** `server/src/shared/sms.ts`에 제공자 구현 — 고칠 곳은 파일 안 **두 군데**뿐

## 예상 일정

```
월요일   1번(인프라 요청) + 2번(네트워크 확인)
         └ 동시에 3번(데이터 입력) 시작 — 자료를 기다릴 필요 없음
```

**병목은 코드가 아니라 ① 인프라 자료 ② 지침 데이터 입력입니다.** 둘은 동시에 진행할 수 있습니다.
